I agree with your approach. We should establish a proper foundation before students touch Linux or AWS.

For students coming from non-technical backgrounds, the first responsibility of a trainer is to remove the fear of technology. They should understand the digital world around them, become familiar with computers, understand the Internet, and learn how devices communicate.

1. Part 0 – Digital World & Networking Fundamentals
2. Part 1 – Linux Fundamentals & Administration
3. Part 2 – AWS Cloud Computing & Architecture

The most important principle is that students should understand what is happening and why before learning commands or cloud services.

## Module 0.12 – Basic Network Troubleshooting

Before Linux, students should also know how to investigate connectivity problems.

| Command         | Purpose                                         |
| --------------- | ----------------------------------------------- |
| `ipconfig`      | Display Windows IP configuration                |
| `ipconfig /all` | Display detailed network information            |
| `ping`          | Test reachability                               |
| `tracert`       | Trace network path on Windows                   |
| `nslookup`      | Investigate DNS resolution                      |
| `arp -a`        | Display ARP entries                             |
| `netstat -an`   | Display network connections and listening ports |
| `hostname`      | Display computer hostname                       |

Teach these exercises in order:

```
# 1. Test the local TCP/IP stack
ping -c 4 127.0.0.1

# 2. Check connectivity to your gateway
ping -c 4 <GATEWAY-IP>

# 3. Test Internet connectivity by IP
ping -c 4 1.1.1.1

# 4. Test DNS resolution and connectivity
ping -c 4 example.com
```

These are Linux commands; you can demonstrate the equivalent Windows commands first and revisit these during Linux training.

Explain that a failed ping does not necessarily mean the destination is down because ICMP can be blocked.
